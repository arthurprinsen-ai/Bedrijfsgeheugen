# Mandatory incident-to-learning closed loop

This skill is an enforcement policy applied by each **existing** Powerhouse, ONE BRAIN, Heartbeat, social/content, Mira/Instagram, SEO/CRO, email, blog/CMS, growth/revenue, portal and engineering agent. It does NOT grant a capability, schedule, publisher, duplicate bypass, video approval or ability to change external data.

**Before action:** read today's original canonical evidence and any matching original ONE BRAIN failure `fingerprint`, occurrences, prevention rule, regression and exact provider-side existing effect. An incident that previously recurred must change the cause/source selection or stop with a typed unmet recovery obligation. Repeated provider retries with the same rejected post, story family, stale source or media SHA are forbidden. Keep the original daily executor active.

**On first or repeated fault:** record exact typed error, provider/source evidence, original canonical owner, occurrence ID and business date in original ONE BRAIN using the existing exclusive writer/authorized RPC. Classify `OBSERVED` / `VALIDATED` where appropriate, never `PROVEN` from a bug ticket or generated artifact. A previously approved source being available does not prove publish success; a former quota 429 is not the current root cause once the identical approved provider has successfully returned fresh content.

**Prevent before retry:** trace why the fault passed upstream. Prefer a **pre-generation** source/recent-story-family exclusion, actual source/date validation, CMS review or video face gate rather than an endless downstream retry. Express one bounded machine-checkable invariant as regression test and change only within the existing original code path. Review authorization, idempotent provider side effects, original unique leases, protected GitHub PR/Required/CodeQL, deployment parity. Update existing agent/skill, human runbook and portal/Brain projection; do not create a second writer, scheduler, fallback (Make/Buffer), alternate provider or bypass.

**Prove and measure:** inspect actual original production behavior and new provider ID / final URL and independent readback. For Instagram, native muted 1080x1920 8-second continuous video, face similarity **at least 0.940 on start/middle/end**, temporal proof and official Meta acknowledgement are hard gates. For email, actual authorized sender, opt-in and suppression. For blog, accurate current official dates, CMS editorial approval, protected deploy and public URL. For LinkedIn, recent story-family deduplication before generating new copy and exact original publisher receipt. Repeat the regression on natural subsequent runs; use real outcome evidence and never mark GREEN from generation, scheduler success, HTTP200 or unverifiable guesses.

**Escalation:** human consent, approvals and payment remain ACTION_REQUIRED without bypass; recurrent source issues must be automatically observed and owned, with safe independent lanes progressing. Keep the parent incident open until the particular error's prevention **and** genuine end-to-end effect are demonstrated. When prevention cannot be verified, record `PROOF_PENDING` with precise next action and original owner in ONE BRAIN/Heartbeat and portal.
