# Powerhouse Development Integration

## Non-negotiable invariant

A material development change is never an isolated implementation. It is a change to the Powerhouse organism.

Fingerprint: `development|whole-brain-portal-skill-integration|v1`.

## Before building

1. Read current Powerhouse state, System Map, open obligations and relevant learning/skills.
2. Reuse existing authority, data store, capability, evidence path and UI surface before creating another one.
3. Produce a Brain impact analysis covering:
   - evidence/provenance;
   - knowledge/memory;
   - graph/relations;
   - semantics;
   - signals/external intelligence;
   - prediction/foresight;
   - impact/value;
   - decision intelligence;
   - agents/execution;
   - delivery;
   - learning/prevention;
   - governance/security/privacy;
   - resource/sustainability.
4. Identify relations to existing business domains, capabilities, data sources and outcomes.
5. Determine Portal V2 impact and skill/learning impact.

## While building

- Extend the canonical loop; never create a parallel brain, dashboard truth, queue, store or learning path.
- Register create/rename/retire/rewire changes in the canonical System Map.
- Preserve provenance, tenant isolation, evidence identity and existing truth boundaries.
- Connect the change to decision/outcome/learning where meaningful.
- If customer/directie/MT/operator value exists, surface the intelligence contextually in the existing Portal V2/cockpit.
- If no portal surface is appropriate, persist `NO_PORTAL_SURFACE` with a concrete reason.
- Convert reusable behavior, incident prevention and new capability knowledge into canonical learning, then verify deterministic skill projection.

## Definition of Done

All applicable items must be proven on the same lineage:
- local regression/tests are green;
- cross-Powerhouse integration regression is green;
- System Map registration/readback is current;
- Portal V2 functional readback is green or `NO_PORTAL_SURFACE` is justified;
- protected merge/promotion and production/provider readback are proven;
- outcome/value evidence is written;
- learning/prevention is canonical;
- skill projection is current and discoverable to future chats/agents.

A PR, merge, deploy or local test is never enough by itself.

## Inheritance

Every current and future chat, agent, workflow and material skill inherits this contract through `AGENTS.md` and `powerhouse-continuity`. Specialist skills may add stricter rules, never weaker ones.
