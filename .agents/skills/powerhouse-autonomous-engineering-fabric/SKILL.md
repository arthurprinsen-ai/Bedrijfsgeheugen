# Powerhouse Autonomous Engineering Fabric v3

Fingerprint: `powerhouse|autonomous-engineering-fabric|v3`.

## Purpose

Turn chats and agents into one coordinated software factory. Specialists work in isolated work packages; one integration agent owns the coherent candidate. GitHub sees fewer, higher-quality candidate heads while agents remain parallel before integration.

## Mandatory execution model

1. Decompose material work into explicit work packages with paths, dependencies, mutable resources and capabilities.
2. Classify risk R0-R4 from the actual changed surface.
3. Build an impact graph and run affected tests during development.
4. Route each package to the best eligible specialist using domain/capability fit plus proven historical outcomes when enough observations exist.
5. Run conflict-free packages in parallel, bounded by `config/powerhouse-engineering-tuning.json`.
6. Only `agent-integration-engineer` assembles the shared candidate. Avoid repeated branch-head churn from individual specialists.
7. Keep hot shared closure surfaces late-bound. Generate learning, change documentation, ledger, skill/system-map projections and release evidence only after the functional candidate is coherent.
8. Push one coherent candidate wave whenever possible; superseded heads are disposable execution evidence, never authority.
9. Full protected release gates, exact-SHA identity and production/provider readback remain mandatory.

## Daily self-improvement

`Powerhouse Autonomous Engineering Optimizer` measures current GitHub queue/execution/failure/cancellation behavior and may adjust only bounded tuning:
- max parallel packages;
- candidate batch window;
- fast-path target;
- speculative-execution threshold.

It must never auto-weaken Required, security, CodeQL requirements for security-sensitive work, protected merge, exact-SHA identity or production readback. Tuning is persisted only through a protected PR and can auto-merge only after protected gates.

## Quality behavior

Reuse before create. Prefer existing helpers, components, API patterns, test fixtures and contracts. The code-quality specialist evaluates duplication, architecture consistency, maintainability and design-system consistency before integration. Speed never means bypassing proof; it means removing repeated reasoning, duplicated work, unnecessary CI waves and avoidable merge conflicts.


## Assurance integrity

All engineering optimization inherits `powerhouse|truthful-green-assurance|current-evidence-only|v1`: speed, parallelism, retries and provider failover may reduce latency but may never synthesize green, suppress current required defects, erase historical evidence, duplicate provider side effects or weaken readback. Final health is recomputed from canonical current evidence after the repair.
