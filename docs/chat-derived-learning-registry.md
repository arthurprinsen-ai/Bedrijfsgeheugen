# Chat-derived engineering learning registry

## Contract

Machine-readable source: `brain/memory/chat-learning-registry.json` (`BRAIN-CHAT-LEARNING-v1`).

This registry converts proven chat outcomes into reusable engineering memory. It is not a transcript archive. It stores the stable part agents must reuse: fingerprint, failure mode, root cause, prevention rule and release gate.

## Mandatory behavior

Before material work, agents search this registry and the shared team context for matching fingerprints. A known failed approach may not be repeated without new evidence. A solved issue is not Definition-of-Done until the prevention rule is encoded in a test, validator, workflow gate or explicit contract and the material outcome has been written back through the shared Brain.

## Current high-value learnings

The registry currently captures branch drift, exact-SHA production proof, protection of concurrent work, import-versus-execution mistakes, canonical footer single-source governance, SEO keyword ownership, bounded retries, outcome verification, independent delivery lanes, mandatory writeback, real preview-before-production and the protected V18 mutation boundary.

## Update rule

When a new chat produces a material ERROR, RECOVERY, IMPROVEMENT, CONTRACT_CHANGE, MISSED_OBLIGATION, AUTO_REPAIR, PRODUCTION_PROMOTION or PRODUCTION_ROLLBACK, add or update one deduplicated fingerprint instead of creating a parallel memory system. Preserve failed approaches when they are useful to prevent repetition.
