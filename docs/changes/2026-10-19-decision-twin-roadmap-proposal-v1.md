# MKB Decision Twin — van scenario naar verantwoord onderzoek

## User value
The existing Brein/Heartbeat/Powerhouse foresight allows an entrepreneur to test an assumption and, when real tenant history supports it, save that hypothesis as a **draft** to the existing roadmap. The roadmap requires an owner, review and verification before any real intervention. It records the inputs instead of fabricating Euro ROI.

## Implementation
- Extend current `portal-v2/decision-twin-receipt.js` with a pure, deterministic, fail-closed scenario proposal builder.
- Extend `portal-v2/foresight-scenario-studio.js` with a consent-driven save button, live context recheck, existing domain-state write and server flush.
- Add `tests/brain-decision-twin-roadmap-proposal-v1.test.mjs`, structured learning, skill and canonical system-map registration.
- Preserve all other portal controls, AI selector governance and supplier evidence gates.

## Remaining product objectives
1. Verified tenant financial time series and independent calibration; no use of global market forecasts as fictitious customer finance.
2. An authorization and provider execution flow with immutable receipts.
3. Measurement design and backtesting, causal control groups where supportable, and realized value.
4. Editorially approved CMS publication; zero published items in the last exact database inventory.
5. Continued observability of growth queue aged backlog and Netlify 499 client disconnects.

## Release acceptance
Protected Required CI and CodeQL must pass; guarded merge; Netlify production exact SHA and authenticated interaction checks. A "ready" deploy alone never implies realized value, a live CMS article or a working commercial action.
