# Eén commerciële Powerhouse → ONE BRAIN → Heartbeat → CRO-groeilus
Datum: 30-10-2026. Oorspronkelijke eigenaren: bestaande Daily Publisher, Growth & Revenue OS, SEO Order Engine, CRO Event Agent, Email Reply Learning, ONE BRAIN/Heartbeat. Original parent issue #4198.

## Probleem en werkelijke bron
Bestaande data en deelkaarten zijn gekoppeld, maar het origineel portaal laat social engagement, e-mailantwoorden, website, consented CTA, lead en betaalde omzet als losse controles zien. Agents moeten zelfstandig op één actuele commercieel relevante oorzaak kiezen, zonder ontbrekend bewijs als nul conversie of een stijging te presenteren. Productiemeting: 32/32 technische lagen, 18/18 jobs actief; 15-lussenbron 8 groen/3 oranje/4 rood; 938 kansen en €0 onafhankelijke gerealiseerde omzet in oorspronkelijke revenue-flywheel. 4.464 pagina-events zonder botvlag over zeven dagen, 0 persistente CTA-clicks, 0 gekoppelde kwalificatierecords of providerreferentie-orders over 30 dagen. Dit betekent niet 4.464 unieke mensen of bewezen 0 echte bezoekers/kopers; tracking/freshness, opt-in en providerbewijs zijn afzonderlijk onzeker.

## Concrete gebouwde originele uitbreiding
Pure originele API-helper `netlify/functions/_powerhouse-commercial-growth-funnel.mjs` projecteert acht stappen: (1) LinkedIn/Instagram 48h views, likes, comments, reposts; (2) social/connectie → website bewijs (NOOIT persoon afleiden); (3) mail → provider-antwoord; (4) afgesloten-week website interactions; (5) exact persistente consented CTA event-ID; (6) vrijwillig opt-in lead; (7) werkelijk betaalde order met onafhankelijke provider/tenant-attributie; (8) op volgende natuurlijke agentactie toegepaste leerregel. Elke stap toont bron, kwaliteitslabel, waargenomen waarde of null, originele verantwoordelijke agent en exact vereist bewijs. De gerangschikte herstel-/CRO-opdrachten worden dynamisch berekend vanuit originele bronnen met `PROPOSED_NOT_EXECUTED` status. Het resultaat verschijnt uitsluitend in de oorspronkelijke admin-only Portal V2 `Andere data`, boven de bestaande three-loop en Innovation Lab kaarten.

Geen nieuwe database, Netlify endpoint, publiek trackingmateriaal, agent, provider, contactlijst, scheduler, publicatie, betaalhandeling of externe kosten. Bestaande server Netlify Identity/Powerhouse admin en de oorspronkelijke 15-lussenreadback blijven ongewijzigd.

## Praktisch CRO-prioriteitsbesluit voor bestaande agents
Eerst bestaande consented CTA eventproducer → original growth-event 202 → drain → exact persistente ID readback beoordelen. HTTP 202/204 bevestigt op zichzelf geen werkelijk opgeslagen CTA. Bij ontbrekend eventbewijs meetdekking repareren en dan gecontroleerde content/CTA-variant met echte behandeling en holdout starten; alleen met toestemming. Daarna echte lead/contactopt-in bronattributie, betaalde providerorder en een werkelijk volgende natuurlijke skilltoepassing, met onafhankelijke klantwaarde. Voor social/SEO vergelijk je 48-uurs leeftijdsgelijke provider snapshots en 7 afgesloten website dagen met 7 vorige afgesloten dagen, nooit cijfers van onvergelijkbare periodes optellen. Voor e-mail gelden provider reply-/thread IDs, echte reactie, toestemming en geen herhaalde verzending.

Alle agents moeten daarna concreet safe code of skill verbeteren via bestaande exclusive-writer beschermde PR Required/BRAIN/CodeQL, exacte GitHub main→Netlify en provider/browser readback, terugschrijven in dezelfde ONE BRAIN fingerprint en volgende natuurlijke run opnieuw meten. Verhoogde views, likes of gekopieerde marketingtrends zijn geen bewezen orderwaarde; daadwerkelijke succesvolle conversie moet onafhankelijk meetbaar zijn.
