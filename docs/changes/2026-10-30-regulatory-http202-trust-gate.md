# Regulatory Source Watch — HTTP 202 is geen geverifieerde wetswijziging

**Datum:** 30 oktober 2026. **Canonieke eigenaar:** bestaande `regulatory-source-watch` in Powerhouse → ONE BRAIN → Compliance/Portaal. **Incident:** `powerhouse|regulatory-source-watch|202-body-claimed-as-legal-change-and-gh-app-policy|20261030-v1`.

## Waargenomen productieincident
GitHub Actions-run [41036966479](https://github.com/arthurprinsen-ai/Bedrijfsgeheugen/actions/runs/41036966479) haalde wettelijke bronnen op en schreef een ruwe observatie in de bestaande Supabase Brain-registratie. De EUR-Lex AI Act-bron gaf **HTTP 202**, een HTML-document van 2.035 bytes. De oude monitor behandelde de andere hash van dit niet-gevalideerde antwoord als inhoudelijk gewijzigde regelgeving. Hij creëerde de onverwerkte branch `writer/regulatory-source-watch/41036966479`, commit `3852c965c95d26713216178eaca02e79d43a2263`; de PR-stap mislukte onafhankelijk: `GitHub Actions is not permitted to create or approve pull requests`. Er is **geen** bevestigd bron-/juridisch wijzigingsbewijs en geen geverifieerde content- of wettelijke statuswijziging op main.

## Oorzaak en herstel
De canonieke `tools/regulatory-source-monitor.py` controleerde alleen een hashverschil. Nu wordt brongezag beoordeeld vóór `changed` en `firstObservation`: uitsluitend HTTP 200 met niet-lege, niet herkenbaar uitgedaagde HTML is geschikt als inhoudelijke bronbaseline. HTTP 202, lege HTML en herkenbare challenge-/CAPTCHA-pagina's worden als `UNVERIFIED` vastgelegd. De laatste geverifieerde baseline blijft onveranderd; bij geen eerdere bevestigde bron mag geen nieuwe baseline ontstaan. Bij onbevestigde HTTP 202/lege/challenge-respons schrijft de nieuwe monitor **geen ruwe HTML** naar een bestandenpad of juridische baseline. Alleen HTTP-status, inhoudshash, tijd en afwijsreden worden via het bestaande Brain-heartbeat vastgelegd. Ruwe bytes worden alleen van werkelijk vertrouwde, inhoudelijk gewijzigde HTTP 200-bronnen vastgelegd. De bestaande `tools/regulatory-brain-ingest.py` publiceert voortaan `observation_trusted`, `unverified_reason` en `freshness_heartbeat=false` wanneer de bronrespons niet is bevestigd. Er is geen tweede scheduler, nieuwe regulatorische bron, nieuw compliance-oordeel of los AgentOS geïntroduceerd.

## Tweede, onafhankelijke fout: GitHub PR-autorisatie
De workflow gebruikt `GITHUB_TOKEN` en heeft op die run geen toestemming om zelf een PR te maken. Een historical config beweert voor eerdere writer-runs `RESOLVED_VERIFIED`, maar dit **actuele** providerbewijs heeft voorrang voor de Regulatory Source Watch-run. **Niet** automatisch Actions-policy, branchbescherming of tokens verruimen. Een echte geverifieerde toekomstige inhoudswijziging vereist PR-overdracht via reeds goedgekeurde providerrechten en exacte branch-/main-/source-ID; de bestaande autorisatieblokkade blijft apart OPEN tot zijn eigen actuele providerbewijs slaagt. Deze source-trust-PR lost de GitHub-toestemmingsgrens niet stilzwijgend op.

## Regression, portaal en onafhankelijke uitkomst
`tests/brain-regulatory-http202-source-trust-20261030.test.mjs` voert de echte Python-monitor lokaal met geïsoleerde fixtures uit: HTTP 202, lege respons, challengepagina en geldige HTTP 200, plus de Brain-ingest metadata. Bestaande `tests/regulatory-organism-feed.test.mjs` en de oorspronkelijke repo-writer-controles blijven intact. Bestaande ONE BRAIN-bronobservaties en Powerhouse-portaal tonen betrouwbaarheid als eigen veld; een source-freshness heartbeat is geen waarheidsclaim over de AI Act.

Bewijspoorten: protected Required / BRAIN / CodeQL → merge naar main → originele volgende natuurlijke regulatory-sourcerun → HTTP-status en change-beslissing onafhankelijk teruglezen → pas bij echte 200-wijziging door bestaande compliance/portaal-review. Bescherm de bestaande unmerged 202-branch tegen automatische goedkeuring. Geen ongefundeerde juridische of commerciële GREEN.
