## Bounded recovery of the original producer

The existing media router's genuine quality-failure preflight now includes a machine-readable `preventive_recovery` object. It is truthful read-only information, not an autonomous publish approval. Face rejects prescribe checking full-bleed 9:16 geometry and the unchanged original master; temporal rejects prescribe a real continuous one-take motion scene. Each proposal carries the actual rejected provider history, source winner, scene, original project/master, budget cap and independent proof requirements.

The original Instagram agent skill now requires using those failure-specific instructions **before** another chargeable generation, deduping previously rejected histories and checking provider budget. The original renderer/publisher gates and same-day one-shot Meta publication rule remain unchanged; no fake green, unverified re-encoding, arbitrary reference substitution, photo-post masquerading as a Reel, direct external send, second scheduler or additional queue.

## Acceptance and nonclaims

- Run deterministic Node regression for measured face=0.920 and temporal=0.890, plus missing proof, wrong frozen source and already-sent protections.
- Exact-head GitHub Required/CodeQL, protected merge, release, and verified active Edge code readback.
- A new OpenArt candidate is **not** an approved video merely because it generated or has the right dimensions. Independent start/middle/end facial confidence ≥0.940 and temporal ≥0.900 remain mandatory.
- Instagram may be reported `LIVE_PROVEN` only with Meta post ID/permalink, provider readback and canonical evidence.
- This change improves agent recovery decisions but alone does **not** generate a passing Reel or guarantee an external generative model will pass every time.
