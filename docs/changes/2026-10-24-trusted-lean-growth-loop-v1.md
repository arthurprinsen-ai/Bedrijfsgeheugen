# Trusted Advisor × Lean Startup — daily growth decision improvement

The canonical daily content-growth learner now structures evidence into small falsifiable hypotheses before suggesting further optimization. It carries observed aggregate signals, counterfactual explanations, a proposed reversible treatment, qualified commercial success metrics, horizons (T+1/T+3/T+7/T+30), safety/trust guardrails and an explicit authority boundary.

Existing canonical owners remain authoritative: `public.powerhouse_experiment_decision_queue_v1`, `public.powerhouse_experiment_learning_v2`, `public.powerhouse_prediction_intelligence_control_v2`, `public.powerhouse_forecast_quality_v2`, `public.powerhouse_outcome_memory_v1` and `config/trusted-advisor-os.json`. No second scheduler, experiment assignment service, customer profile, separate forecast database or autonomous production promotion is introduced.

When the repository input lacks independently verified provider metrics, the output is `NEEDS_VERIFIED_LEARNING_INPUT`. An external market signal with an expired deadline remains research context, not a current actionable campaign. A detected pattern never establishes a causal explanation; a challenger is never automatically declared a winner.

Customer self-discovery requires verified authenticated tenant-specific evidence, explicit goals, human decision rights and confidentiality safeguards. This is a **read-only aggregate advisory projection**, not an already live per-customer agent. That separate production obligation remains open until legitimate tenant-bound runtime and customer readback are verified.

Validation: `node --test tests/brain-trusted-lean-loop-v1.test.mjs`, existing daily artifact, protected Required and CodeQL, production source readback.
