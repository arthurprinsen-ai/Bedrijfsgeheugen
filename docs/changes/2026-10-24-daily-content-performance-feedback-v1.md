# Daily content improvement — genuine posts, blogs and website evidence

The existing Powerhouse daily Content growth learning workflow now **attempts** a bounded, tenant-filtered, read-only source observation. It uses the already established protected GitHub `SUPABASE_ACCESS_TOKEN` and the documented Supabase management read-only SQL endpoint. It queries the owned brand's canonical social post snapshots, consented nonrobot page events and data-source health, then attaches a deterministic per-post/per-page diagnostic to the existing daily learning artifact. It does not create a parallel scheduler or database.

For social, the diagnostic keeps missing LinkedIn view counts unknown. It uses mature recent provider observations to propose focused hook/situation/consequence/pointe/CTA tests, without claiming low engagement proves a particular cause. For blog and commercial pages, an aggregate of page and click sessions is **not** treated as a lead or sale; attribution remains unknown without observed downstream events. The output retains GA4/Search Console/provider quality gaps and routes small reversible hypotheses through existing Powerhouse experiment and publisher controls, without directly publishing unreviewed content.

A missing/invalid API token or provider failure is recorded as `AUTH_REQUIRED` or `SOURCE_ERROR`. The mere presence of the script or a successful GitHub scheduler is not evidence that all provider metrics have flowed through. Real scheduled provider readback, protected delivery, publication and realized order/revenue outcomes remain independently required.
