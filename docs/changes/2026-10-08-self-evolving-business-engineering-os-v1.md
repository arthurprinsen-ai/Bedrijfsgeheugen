# Self-Evolving Business & Engineering OS — cross-domain evolution v1

## Why
POWERHOUSE already has ONE BRAIN, the Organism dependency graph, a Self-Improvement Layer, canonical evidence/outcome registries, and protected engineering delivery. Adding a new brain would fragment truth. This iteration connects those existing authorities at the *decision boundary*.

## Implemented policy
The pure planner `brain/self-improvement/cross-domain-evolution.mjs` produces a deterministic, tenant- and source-revision-bound proposal. It propagates AI/connector/policy changes through existing dependencies, identifies GDPR, AI Act, NIS2/Cbw, security, and CSRD/ESRS applicability reviews, and records what is missing. It accepts only fresh, independently evidenced, executed-and-observed outcomes from business and engineering; provider receipts and production readbacks are distinct from action requests. A control-group comparison tied to the same policy versions is required before claiming causal improvement. All existing candidate quality/security/regression/cost/latency checks remain authoritative.

## Execution boundary
The output is `PROPOSED_NOT_EXECUTED`. Existing canonical Brain obligations/outbox own durable execution; existing GitHub protected delivery owns code rollout; Netlify/Supabase/provider readback owns actual completion. **No new cron, queue, database, API endpoint, automatic production writer or external message sending has been introduced.** Planner acceptance is not proof of operational closed loop.

## Regression and proof
Run `node --test tests/brain-self-evolving-business-engineering-os-v1.test.mjs`. Then require protected CI, same-commit main merge, exact provider production readback, and measured post-deployment outcomes before claiming LIVE. This PR must remain a candidate until those gates pass.
