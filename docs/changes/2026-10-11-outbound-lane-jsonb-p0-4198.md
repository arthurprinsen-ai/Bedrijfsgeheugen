# P0 #4198 — JSONB receipt correctness for independently running commercial channels
At 11:02Z the production commercial Heartbeat executed all four lanes and wrote separate durable hourly receipts, but the JSONB evidence and context values were strings containing JSON, rather than JSONB objects. As a result `evidence->>'decision'` yielded null. This is a readback defect, not a missing lane run. Use explicit `::text::jsonb` on the two input parameters and the evidence merge parameter so PostgreSQL parses a real JSONB object instead of applying double JSON serialization. The existing sender eligibility and no-duplicate/consent/pressure controls are unchanged. Historical receipts can be normalized without modifying delivery proof, or left immutable if existing lineage rules require it. Validate source parity, provider project deployment, and live `jsonb_typeof(evidence)='object'` after the next canonical Heartbeat. Sender ACK is not implied by a status receipt.
