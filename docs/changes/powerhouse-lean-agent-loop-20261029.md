# One evidence-driven Lean improvement loop for all agents

Date: 2026-10-29 · Obligation-ID: powerhouse-lean-agent-loop-20261029 · Status: SOURCE_CANDIDATE_NOT_LIVE

All agents already use ONE BRAIN, Powerhouse, Heartbeat and canonical incident fingerprints. This PR **extends their existing default preflight** instead of creating a competing AI orchestrator, database, writer or scheduler.

## Operating cycle
**MEASURE → ANALYZE → HYPOTHESIZE → PRIORITIZE → IMPLEMENT → VERIFY → LEARN → REMEASURE.** Every material worker asks what can be better, smarter, faster, and what improves independent customer/revenue value. Actions and failures record scope, owner, evidence, before metric, intervention, provider/test proof, after metric and learning. Evidence must be privacy-minimal and tenant-safe.

## Data gaps first, not invented zeros
A missing metric triggers one deduplicated instrumentation obligation in the existing Brain lineage and must be implemented through the authorized owner, tested and independently observed in the portal. Do not equate unavailable attribution with zero clicks or orders. For instance, existing 14-day growth_page_daily projects 3,634 views but zero CTA/leads/orders, while privacy-protected interaction events and 26 scan completions exist. Source reconciliation and attribution should be investigated before CRO conclusions or conversion claims.

## Release and scope
This patch is a **machine-checked agent policy/preflight candidate** with regression tests. Existing Supabase Edge Functions, portal read-models, social/email writers and sales execution are NOT thereby instrumented or deployed. Their follow-up must reuse the same exclusive writer, obligations and source registry, with no data leaks or added schedule. Required, BRAIN, CodeQL, preview, protected landing and independent origin/provider proof remain mandatory. The meaningful goal is verified leads, won orders and paid revenue—not generated posts, impressions or PR merges.
