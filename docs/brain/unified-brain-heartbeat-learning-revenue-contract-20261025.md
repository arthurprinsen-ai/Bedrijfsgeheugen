# Unified Brain–Powerhouse–Heartbeat learning & revenue contract
Date: 2026-10-25
Status: proposed; not a production deployment
Owner: existing Powerhouse orchestration and Brain canonical memory; no new scheduler, writer, queue or duplicate data store.

## Non-negotiable operating contract
Every material build, edit, deployment, incident, outbound communication, recommendation, customer intervention and experiment must emit or reconcile one evidence-linked canonical event in the existing Brain mechanism. Reuse existing registers and derived skills, rather than establishing a competing memory authority. Record event ID/fingerprint, correlation and obligation IDs, tenant/scope, source and consent classification, agent/skill/version, trigger, evidence URL/provider ID, code SHA, action, timestamps, decision and rationale, before/after metric, validation status, failure classification, result, owner and next action. Redact credentials, personal data and tenant-private material; enforce tenant separation, retention and deletion policies. Do not log raw secrets or unnecessary personal identifiers.

## One execution loop
1. OBSERVE: daily existing Heartbeat/Janitor cadence ingests authorized first-party analytics, search, CRM, messages and external evidence with provenance, timestamp, freshness and tenant boundaries. Expose relevant external signals inside each customer's portal with source, relevance, confidence, recommended action, due date and result.
2. UNDERSTAND: reconcile source signals with actual customer state and historical incidents, known-error fingerprints, previous hypotheses and skill evaluations. Distinguish facts from estimates and missing data.
3. DECIDE: rank opportunities by expected *incremental verified business value*, customer impact, evidence quality, effort, risk, consent and feasibility. Deduplicate using canonical obligation IDs. Use a deterministic policy layer for access, budgets, data protection and production change.
4. ACT: existing owner agent plans bounded, idempotent interventions. Parallel analysis is allowed; a single approved writer per resource. Sales outreach only when lawful, relevant and consent/legitimate-interest assessment and provider constraints permit. No deceptive personalization, spam or fabricated performance claims.
5. VERIFY: independent provider readback and real outcome evidence. Social is published only with external post/media ID and readback; releases only with current Required, CodeQL, native preview and protected main + production readback; payments only with reconciled paid order/payment records. An ACK or generated content is not a result.
6. LEARN: compare predicted and actual outcome, persist failure/success fingerprint and delta, revise skill candidate plus bounded evaluation tests. Repeated failures update the same fingerprint, not new duplicate issues. Promote skills only after regression/security/quality evaluation, review policy and rollback path. Keep learning independent of unrelated freshness/provider failures.
7. REPEAT: existing cadence reads the same canonical state on subsequent cycles, checks overdue obligations, and escalates only blocked external authorization, security, financial or evidence dependencies. Never manufacture a green status.

## Outcomes and leading indicators
- Customer portal: recommendations seen/accepted, time to action, completed actions, verified savings/benefit (with customer confirmation and attributable baseline), retention and service quality.
- Acquisition: qualified target accounts, legally contactable leads, valid outreach, actual provider deliveries, replies, meetings, scan completions with explicit permission, proposals, won orders, paid and reconciled revenue.
- CRO: consented anonymized funnel entry, stage abandonment, hypothesis, changed variant, baseline, cohort, experiment window, statistically defensible or descriptive result, next action.
- Operations: incident recurrence, mean time to detect/recover, skill evaluation pass rate, provider/readback coverage, tenant isolation and regressions.
No engagement metric (views/likes) is a revenue proxy without validated downstream attribution.

## Release/decision states
PLANNED -> EXECUTING -> PROVIDER_VERIFIED -> OUTCOME_VERIFIED -> LEARNED. BLOCKED and FAILED are explicit; recovery preserves full lineage. Aggregate GREEN requires all mandatory gates and evidence on the current production identity. A dashboard must show unknown/unverified separately from zero and success.

## Initial integration acceptance checklist
- Map existing Brain schema/learning logs/skills and current Heartbeat cadence; choose existing canonical event+obligation interfaces and version this contract there.
- Add regression test for event schema, idempotent fingerprints, provenance, privacy/tenant isolation, missing-proof status, policy-denied writes and independent result readback.
- Wire content/social/CMS/SEO/CRO/CRM/portal/sales flows to the shared canonical event and obligation interfaces only after impact and permission review.
- Project verified lessons into existing .agents/skills/powerhouse-continuity/SKILL.md with source IDs and evaluation history; do not auto-approve code or grant tools greater privileges.
- Expose customer-specific prioritized insight → explanation → recommended action → proof → follow-up in the portal without leaking other tenants' data.
- Verify actual scheduled run, exact current branch checks, protected merge, deployment, provider proof and next-cycle learning before claiming LIVE.
- Track all unimplemented checklist items as open obligations, not completed or green.
