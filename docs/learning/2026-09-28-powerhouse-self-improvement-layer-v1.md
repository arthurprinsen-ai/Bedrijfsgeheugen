# Learning — Powerhouse Self-Improvement Layer v1

## Why this exists

Powerhouse already contained strong intelligence, learning and engineering capabilities, but they were distributed across several canonical subsystems. Local improvements could therefore be correct without proving that the whole system became measurably better.

## Root cause

There was no single cross-layer contract joining Company Graph context, verified outcomes, explicit agent objectives, model selection, architecture health, candidate evaluation and protected promotion.

## Resolution

The Self-Improvement Layer composes the existing authorities into one loop:

`Observe → Detect → Hypothesize → Build → Test → Evaluate → Compare → Promote → Measure → Learn`

It deliberately reuses existing Outcome Memory, optimization candidates, quality events, model health, autonomous improvement and protected delivery. No second graph, outcome ledger, learning store or uncontrolled production writer is introduced.

## Prevention

- No learning without evidence.
- No change without evaluation.
- No deployment without regression proof.
- No intelligence without measurable outcome.
- Unknown is never green.
- Architecture degradation can block promotion.
- Model routing remains provider-neutral and constrained by privacy, capability, quality, reliability, cost and latency.
- Verified learning is compiled into regression protection, skills, documentation, System Map updates and bounded change candidates.
